# 루프 작업 안내

Claude가 `/loop`으로 혼자 이어서 일할 때 읽는 문서. 한 바퀴에 할 일 하나를 끝내고 기록한다.
규칙의 근거는 [CLAUDE.md](../CLAUDE.md)(안전 원칙), 지금까지의 상태는 [HANDOFF.md](HANDOFF.md)에 있다.

## 한 바퀴의 순서

0. **다시 읽기.** 바퀴마다 이 문서와 CLAUDE.md의 안전 원칙을 처음부터 다시 읽는다. 대화가 요약돼도 규칙과 목록은 여기 있다.
1. **상태 확인.** Git Bash에서는 먼저 `export PATH="$(cygpath -u "$APPDATA")/npm:$HOME/.cargo/bin:$PATH"`.
   - `git status`에 변경이 있을 때: `[~]`(진행 중) 항목의 작업이면 이어서 하거나, 이어 갈 수 없으면 되돌리고 그 항목을 다시 `[ ]`로 둔다. 그 밖의 변경(사용자 것일 수 있음)은 손대지 않고 루프를 멈춘 뒤 알린다. `.claude/`는 사용자 설정이라 원래 커밋하지 않는다.
   - 이전 바퀴의 테스트 흔적이 남았을 수 있으니 테스트 앱을 썼던 항목 뒤라면 `cargo run -p robin-fixture -- remove`.
2. **할 일 고르기.** 아래 목록에서 위쪽부터 `[ ]`인 첫 항목. 🔒 표시가 있으면 건너뛴다. 고른 항목을 `[~]`로 바꾼다.
   항목이 한 바퀴에 끝나지 않을 만큼 크면(대략 파일 10개나 400줄이 넘으면), 먼저 그 항목 아래에 작은 조각들로 나눠 적고 첫 조각만 한다.
3. **만들기.** 항목의 "끝난 기준"을 그대로 따른다. 관련 없는 파일은 고치지 않는다.
4. **확인.**
   - 앱 코드: `pnpm check` 통과. 화면이 바뀌면 `pnpm tauri dev`로 띄워 DevTools 포트(9223)로 실제 화면을 본다.
   - 삭제·정리·시작 항목 동작은 테스트 앱(`robin-fixture`)과 디버그 전용 테스트 항목으로만 시험하고, 끝나면 `robin-fixture remove`.
   - 웹사이트: `website/README.md`의 빌드와 taste-skill 검사(FAIL 0), 그다음 `bash website/scripts/deploy.sh`.
   - 문서만 바꿨으면 링크와 명령이 실제로 있는지만 확인한다.
   - 확인용으로 띄운 앱, 개발 서버, 브라우저는 끝나면 닫는다. 앱은 창을 닫는 방법을 먼저 쓴다(`taskkill /F`는 WebView2 프로세스를 남긴다).
5. **기록.** 커밋 메시지는 영어, 끝에 `Co-Authored-By` 줄. `main`에 커밋하고 push한다.
   이 문서의 항목을 `[x]`로 바꾸고 날짜와 커밋 해시를 붙인다. 아래 "바퀴 기록"에 한 줄 남긴다.
6. **보고와 다음 바퀴.** 사용자에게 한국어로 두세 줄 보고한다(한 일, 커밋, 다음 항목). 할 수 있는 항목(🔒 아님)이 남았으면 60초 뒤 다음 바퀴를 예약한다.
   없으면 루프를 끝내고 🔒 항목과 사용자가 할 일을 모아 보고한다.

### 범위를 지키는 규칙

- **목록은 사용자의 것이다.** 루프는 상태 표시(`[ ]`·`[~]`·`[x]`·🔒), 큰 항목 나누기, 기록 추가만 한다. 항목을 새로 만들거나 순서·내용·끝난 기준을 바꾸지 않는다.
- **하다가 발견한 다른 문제나 아이디어**는 아래 "발견한 것"에 한 줄로 적고 지금은 고치지 않는다. 지금 항목을 막는 버그만 예외로 고치고, 커밋 메시지에 따로 적는다.
- 문구 다듬기(B)는 화면에 보이는 문장만 바꾼다. 동작, 구조, 디자인은 바꾸지 않는다.
- 새 의존성 추가, 설정 파일 형식 변경, 사이트 배포는 그 항목이 요구할 때만 한다.
- 같은 항목이 두 바퀴 연속 끝나지 않으면 🔒와 막힌 이유를 적고 다음 항목으로 간다. 세 바퀴 연속 아무 항목도 끝내지 못하면 루프를 멈추고 보고한다.

### 멈추고 🔒로 표시할 때

다음이 필요해지면 그 앞까지 한 것만 확인해 커밋하고, 항목에 🔒와 이유(사용자가 할 일)를 적은 뒤 다음 항목으로 간다.

- UAC "예", 로그인, 저장 창 확인처럼 사용자의 손이 필요한 것
- GitHub Release 공개(`scripts/release.sh --publish`) 같은 공개 행동
- 정한 원칙(삭제 원칙, 만들지 않는 기능)이나 기본값을 바꾸는 결정
- 외부 서비스에 무엇을 보내거나 계정 설정을 바꾸는 것 (예외: G의 규칙 안에서 하는 Anthropic API 호출은 사용자가 승인함)

### 절대 하지 않는 것

- 실제 프로그램 제거, 실제 잔여물·캐시 삭제, 실제 시작 항목·설정 변경 (읽기만 한다)
- 비밀 키(`%USERPROFILE%\.tauri\robinx-updater.key`) 출력·커밋·전송, `docs/private/`·`Revo Uninstaller Pro.zip` 커밋
- Claude API 키(`ANTHROPIC_API_KEY`) 출력·기록·커밋, 앱·사이트·설치 파일에 넣기, api.anthropic.com 말고 다른 곳으로 보내기
- 분석한 외부 프로그램(GPL 등)의 코드 복사
- `pnpm check`가 실패한 채로 커밋. 한 바퀴 안에 못 고치면 내 변경을 되돌리고 항목에 오류를 적어 🔒
- `--no-verify`, 강제 push, 다른 사람이 남긴 변경 덮어쓰기

### G. "이게 뭐예요? 꺼도 돼요?" 설명 사전 (Claude API, 2026-10-19 사용자 승인)

시작프로그램·설치된 프로그램의 "설명"이 `CCXProcess`처럼 파일 이름뿐이라 사용자가 판단할 수 없다. 특히 은행 보안 프로그램
(AhnLab Safe Transaction, nProtect, TouchEn nxKey, Veraport, IPinside, AnySign 등)이 많은 한국 PC에서 쓸모가 크다.
개발할 때만 Claude API로 설명 초안을 만들고, 검토한 결과만 앱에 고정 데이터로 넣는다. **앱이 직접 API를 부르지 않는다.**

G의 규칙 (모든 G 항목에 적용):

- **모델은 `claude-sonnet-5-5`만.** 여러 개를 물을 때는 Message Batches API(반값)를 쓰고, 공통 지시문은 프롬프트 캐시를 쓴다.
- **키:** `ANTHROPIC_API_KEY`. 사용자가 `setx`로 사용자 환경 변수에 넣었으므로, 지금 프로세스에 없으면 사용자 환경 변수(HKCU)에서 읽는다. 값은 화면·로그·파일 어디에도 남기지 않는다 (있는지, 길이만 확인 가능).
- **보내는 것:** 프로그램·시작 항목 이름, 게시자, 실행 파일 이름, 파일 버전 설명만. 사용자 이름이 든 경로(`C:\Users\<이름>`)는 `%USERPROFILE%`로 바꾸고, 그 밖의 PC 정보는 보내지 않는다. 받는 곳은 api.anthropic.com뿐.
- **예산:** 크레딧은 US$100이고 2026-11-10(UTC)에 끝난다. **G 전체 US$20 이하, 한 번 실행에 US$3 이하.** 스크립트는 보내기 전에 예상 비용을 계산해 넘으면 보내지 않는다. 가격은 G1에서 공식 문서로 확인해 스크립트에 날짜와 함께 적는다. 실제 사용량(응답의 usage)은 `docs/ai-usage.md`에 실행마다 한 줄씩 남긴다.
- **같은 질문을 두 번 보내지 않는다.** 응답 원본은 `scripts/ai/out/`(git에 넣지 않음)에 저장하고, 이미 답이 있는 항목은 다시 묻지 않는다.
- **공개 저장소다.** 이 PC에서 읽은 목록 원본은 `scripts/ai/out/`에만 둔다. 커밋하는 사전에는 널리 배포되는 공개 프로그램만 넣고, 개인·회사 내부용으로 보이는 항목은 뺀다.
- **답은 초안이다.** 모르는 프로그램, 확신이 낮은 답은 넣지 않는다. 백신·Windows 보안·업데이트를 "꺼도 된다"고 쓰지 않는다(만들지 않는 기능 원칙). 앱은 설명을 보여 주기만 하고, 설명을 근거로 무엇을 자동으로 끄거나 지우지 않는다.

  끝난 기준: 가짜 응답(제거됨·실패·거절·아직 설치됨 섞기)으로 흐름 끝까지 확인.
- [ ] **I27. 프로그램: 하나 제거 결과와 움직임.** 종료 코드를 모르는 "아직 설치돼 있어요"에서 "다시 시도"가 언인스톨러를 한 번 더 실행한다("다시 확인"으로). 실패 메시지가 `ErrorState`와 달리 가운데 일반 글자라 선택·복사가 안 된다. 제거된 행이 접히며 사라지는 움직임이 대화상자 뒤에서 끝나 보이지 않고 `height`를 애니메이션한다(창을 닫은 뒤에 목록 갱신). 크기 재는 동안 비활성 "목록 내보내기"의 툴팁이 뜨지 않는다. 처음 켤 때 행 등장·크기 막대·숫자 올라가기가 시작 화면 뒤에서 끝나거나 겹친다(시작 화면이 끝난 뒤부터 시작).

**남은 흔적·복구 기록**

- [ ] **I28. 남은 흔적: 정리 결과 화면.** 전부 실패하거나 관리자 권한 항목만 있어도 "0개를 정리했어요 / 백업 폴더로 옮겼어요"가 나온다. 관리자 권한이 필요한 항목이 무엇인지 보이지 않는다(승인 전에 경로를 보여 줌). 결과 위쪽이 스크롤되지 않아 900×600에서 실패 목록이 거의 안 보인다. 보호된 항목 문구가 "안전을 위해 건드리지 않았어요: …건드리지 않았어요"로 겹치고 청록색이라 좋은 신호처럼 보인다. 파일 없는 시작 항목 정리 결과에 1 KB를 두고 "남은 공간은 아직 그대로" 문단이 나온다(작으면 숨김). 시작 항목 하나를 정리하면 Run 값과 짝인 `StartupApproved` 값 두 개가 작업 항목이 되어, 3개를 고르면 "6개를 정리했어요"·"보관 중 6개"가 된다(시작 항목 수로 세기).
- [ ] **I29. 남은 흔적: 창 안의 흐름.** 남은 흔적이 없을 때와 찾기에 실패했을 때 제목이 같다("남은 흔적을 찾지 못했어요"), 빈 결과에도 비활성 "선택 항목 정리" 줄이 남는다. 확인 화면에서 "돌아가기"를 누르면 목록이 다시 마운트되어 스크롤이 맨 위로, 줄 등장이 다시 재생되고, 포커스가 사라진다(정리 오류 때도). 확인 화면에서 Esc를 누르면 창이 통째로 닫혀 선택을 잃는다(돌아가기로). 정리 오류가 아래 줄에 끼어 선택 요약이 두 줄로 깨진다. 전체 선택·해제가 없고 줄을 눌러도 체크가 안 바뀌며 한 줄에 Tab이 네 번이다. 머리글의 X와 "다시 찾기"가 16px 어긋나고, 앱 이름이 길면 부제가 잘려 강제 제거 설명이 사라진다.
- [ ] **I30. 남은 흔적: 잔여물 정리 페이지.** 방금 제거한 목록을 불러오는 중이거나 실패해도 "0"과 안내가 그대로 나온다(로딩·오류 화면). "강제 제거" 버튼 아이콘이 창 안과 다르다. 정리를 마친 앱이 아무 표시 없이 남는다. "보호 규칙으로 N개 제외" 숫자에 사용자가 직접 뺀 항목이 섞이는데(`crates/scanner/src/lib.rs`의 `apply_exclusions`) 문구는 Windows 보호 규칙만 말하고 "살펴보지 않았어요"도 틀리다(둘을 나눠 세거나 문구를 맞춤, "점수와 상관없이"도 쉬운 말로).
- [ ] **I31. 복구 기록: 세부.** 백업마다 언제 지워지는지 보이지 않는다("N일 뒤 지워져요", 가까우면 경고색). 백업 삭제 중에도 X가 보이지만 반응이 없고, 진행 표시가 나타나며 대화상자가 위로 튄다(두 삭제 창 모두). 다 되돌린 기록을 지울 때 "보관 중인 항목 0개가 영구히 지워져요". "오래된 백업 비우기"의 기간 선택이 radio인데 방향키로 안 움직인다. 상태 글자 위치가 줄마다 들쭉날쭉하고 900px에서 앱 이름이 잘린다. 멈춘 항목 상태 "대기"가 곧 처리될 것처럼 읽힌다("중간에 멈춤").

**저장공간·시작프로그램·설정·설치 화면**

- [ ] **I32. 저장공간: 확인 창과 합계.** 휴지통처럼 되돌릴 수 없는 항목만 고르면 "0 KB를 정리할까요?"가 나오고, 아래 줄·디스크 카드·확인 창의 합계가 서로 다른 기준이다. 되돌릴 수 없는 항목에도 "왜 지워도 되나요?"가 붙는다. 결과에서 `needsAdmin`보다 `skipped`를 먼저 봐서 "관리자 권한을 받지 못해 건너뛰었어요"가 나오지 않고, 지운 게 없는데 "고른 항목을 정리했어요"가 함께 나오며, "건너뜀: …건너뛰었어요"로 겹친다. 디스크가 거의 꽉 차도 강조가 없다. "직접 정리할 수 있는 큰 항목"이 권한이 없어 못 센 Windows.old를 "0 KB"라고 하고, `powercfg` 같은 명령이 문장에 묻혀 있다(코드 모양과 복사 버튼). "용량이 큰 프로그램"의 "프로그램 화면에서" 버튼이 문장 조각이고 버튼 폭 때문에 크기 칸이 어긋난다.
- [ ] **I33. 저장공간: 움직임과 큰 폴더·큰 파일.** 디스크 막대의 "정리 예정" 조각이 처음에 막대와 떨어져 떠 있고 선택이 바뀌면 끝이 어긋난다(`width` 대신 `scaleX`, 사용 중 막대 안쪽에 붙이기). 큰 폴더에서 하위 폴더를 누를 때마다 목록이 사라졌다 나와 카드 높이가 튀고 스크롤을 잃는다(지난 목록을 흐리게 남기기). 확장자 없는 파일 종류가 "NOEXT", 큰 파일은 40개·큰 폴더는 30개에서 아무 말 없이 자른다("큰 것부터 40개"), 900px에서 폴더 경로가 뒤에서 잘려 마지막 폴더가 안 보인다.
- [ ] **I34. 시작프로그램: 스위치와 좁은 창.** 켜고 끄는 동안 스위치를 스피너로 바꿔 키보드 포커스가 사라지고 끝나도 돌아오지 않는다(스위치는 두고 비활성·`aria-busy`). 기다리는 동안 상태 칸이 이전 값을 보여 준다. 900×600에서 이름 칸이 "Robin …"으로 잘리고 새로고침 버튼이 혼자 다음 줄로 내려가 고정 머리가 화면의 1/3을 차지한다. 숨은 예약 작업 카드가 UAC "아니요"까지 빨간 오류로 보인다. 프로그램 실행이 아닌 예약 작업은 엔진이 실행 명령 자리에 "(프로그램 실행이 아닌 작업)"이라는 문장을 넣어 보내서, 숨은 작업 카드와 시작 항목 자세히의 "실행 명령"에 고정폭 글꼴로 보인다(엔진은 비워 보내고 화면이 일반 글꼴 문장으로 그림, `crates/startup/src/lib.rs`). 검색해도 필터 칩 숫자가 전체 기준이라 목록 "1개"와 칩 "전체 2"가 어긋난다(프로그램 화면처럼 칩은 검색어 반영). 파일 없는 항목 정리 창의 버튼 순서가 [실행][닫기]라 다른 창([취소][실행])과 다르다(남은 흔적 창 아래 줄도 같음).
  끝난 기준: 가짜 응답으로 확인, 실제 시작 항목은 켜고 끄지 않는다.
- [ ] **I35. 설정과 업데이트.** 보관 기간 확인 창이 닫히는 동안 숫자가 빠져 "일이 지난 백업을…"으로 보이고, 지금 기준으로 몇 개·얼마가 지워질지 알려 주지 않는다(`oldBackups` API 있음). 사이드바에 새 버전이 떠 있어도 설정에는 "업데이트 확인"만 있어 다시 확인한다(바로 설치 창 열기). 릴리스 노트가 없으면 업데이트 창 본문이 제목만 반복하는 빈 상자다(`scripts/release.sh`). 제외 목록 X 버튼은 툴팁이 없고 누르는 동안 막히지 않아 두 번 눌린다. `remove_exclusion`(`src-tauri/src/settings.rs`)이 위치만 비교하고 값 이름은 보지 않아, 같은 Run 키의 값 두 개를 제외해 둔 상태에서 두 번 누르면 다른 항목까지 빠진다(값 이름도 비교). 설정의 업데이트 설명("새 버전이 나오면 창을 띄워")이 실제(켤 때는 창, 쓰는 동안은 사이드바)와 다르다.
- [ ] **I36. 설치 화면.** `setup-app.tsx`. 이미 설치돼 있고 실행 중이면 버튼은 "업데이트"·"다시 설치"인데 경고는 "설치를 누르면". 설치·제거 중 닫기를 누르면 아무 반응이 없다(진행 중이라 닫을 수 없다고 알림). 정보를 읽지 못한 경우에도 "일부만 바뀌었을 수 있어요. 다시 시도해도…"라고 하는데 바뀐 것도 다시 시도 버튼도 없다. "백업과 설정도 지우기"가 시작프로그램 변경 기록(다시 켤 때 원래 값으로 되돌리는 데 씀)도 지운다는 것을 알리지 않는다. "설정 찌꺼기" 표현.
  끝난 기준: 설치 화면은 가짜 응답으로만 확인한다(실제 설치·제거는 CLAUDE.md 규칙대로 RobinX 자신으로만, 이 항목에서는 하지 않는다).

**2차 점검: 움직임·환경·처음 쓰는 사람**

- [ ] **I44. 앱: 단계가 바뀔 때 깜빡이고 창 높이가 튐 (공용 래퍼).** 남은 흔적 창의 확인·정리 중·완료가 `AnimatePresence` 밖에서 바뀌어 `clean-flow.tsx`의 `exit`이 쓰이지 않고, 옛 화면이 바로 사라지고 새 화면이 투명에서 올라온다(찾는 중→결과는 약 170ms 빈 본문). 저장공간 정리 창은 확인→진행→결과로 높이가 269→206→435px로 바뀌며 가운데 정렬이라 위아래로 튄다(시작프로그램 정리 창, 일괄 제거 창, 업데이트 창도 같음). 단계 내용을 교차시키고 바깥이 높이를 짧게 따라가는 공용 래퍼를 만들어 쓰고, 대화상자는 위쪽을 고정해 아래로만 자라게 한다. H7·H8에서 만든 것이 있으면 그것을 넓힌다.
- [ ] **I45. 앱: 찾는 중 테두리 빛과 움직임 줄이기.** 남은 흔적 창을 처음 열어 찾을 때 돋보기의 테두리 빛(`BorderBeam`)이 마지막 위치에 멈춰 있고(`initial={false}`가 첫 자식에 적용), 움직임 줄이기에서는 "다시 찾기" 때 계속 돈다(`offsetDistance`는 `MotionConfig`가 끄지 않음). CSS 애니메이션으로 바꾸고 줄이기에서는 멈춘 모양으로. 로딩 자리표시(`animate-pulse`)도 줄이기 규칙에 넣는다.
- [ ] **I46. 앱: 사이드바를 펼칠 때 아래 안내 카드 글자가 한 글자씩 세로로 쌓임.** 숨김 클래스는 바로 바뀌고 폭은 300ms 동안 바뀐다(t=71ms에 폭 23px·높이 507px). 글자는 `hidden` 대신 투명도로 가리고 안쪽 폭을 고정해 잘리게 한다.
- [ ] **I47. 앱: 움직임 자잘한 것.** Store 탭에서 돌아오면 요약 숫자가 0부터 다시 오르고 카드 등장이 다시 재생된다(H11(다)와 같은 방식으로). 목록↔카드 보기 전환이 교차 전환 위에 카드 차례 등장이 겹쳐 약 1초 걸린다(전환 하나만, 더 짧게). 필터 칩·탭의 선택 알약(`layoutId`)이 폭이 다른 칸으로 옮길 때 모서리가 눌린 타원이 된다(`style`로 `borderRadius`). 프로그램 화면만 페이지를 옮겨 올 때 등장 움직임이 없다. 펼침 화살표(200ms, 기본 곡선)와 펼쳐지는 패널(250~300ms, ease-out-quint)의 시간·곡선이 따로 논다(제거 창, 시작프로그램, 저장공간, 복구 기록). 저장공간을 찾는 동안 항목이 크기순으로 끼어들어 누르려던 줄이 밀린다(찾는 동안은 아래에 붙이고 끝나면 한 번 정렬).
- [ ] **I48. 앱: 많은 프로그램에서 느림.** 설치 프로그램 800개면 검색 글자 하나에 약 220ms(CPU 4배 느린 PC에서 1.4초), 1000개면 첫 행까지 1.8초(느린 PC 12초로 시작 화면 최대 8초를 넘김), 고르기 체크 하나 184ms, 테마 전환 600ms. 가상화·`memo`·`useDeferredValue`가 없다. 입력은 미루고, 행을 `memo`로, 핸들러를 고정하고, `content-visibility`나 가상 목록(새 의존성 `@tanstack/react-virtual` 허용)을 쓴다.
  끝난 기준: 가짜 응답 1000개로 프로덕션 빌드에서 전후 수치를 바퀴 기록에 적는다.
- [ ] **I49. 앱: 새로고침할 때마다 크기 재기가 겹쳐 돎.** 크기 쿼리 키가 목록 갱신 시각이라 새로고침·정리·복원 뒤마다 `measure_app_sizes`가 새로 돌고 이전 것은 멈추지 않는다(0.5초 간격 4번 → 5개 동시). 진행 숫자도 오락가락한다. Rust 쪽에서 돌고 있으면 합류하거나 이전 것을 멈추고, 화면은 이전 쿼리를 취소한다.
  저장공간 "다시 찾기"도 막히지 않아 연타하면 두 찾기가 함께 돌고 진행 숫자가 4/6→1/6→6/6→3/6처럼 오락가락한다(찾는 동안 막고, 진행 소식에 작업 번호 확인).

  끝난 기준: 가짜 응답으로 동시 호출 수 확인, `cargo test`.
- [ ] **I50. 앱: Windows 고대비 모드에서 상태가 안 보임.** `forced-colors` 규칙이 하나도 없어서 스위치 켜짐·꺼짐, 필터 칩·탭·테마·보관 기간·사이드바의 선택 표시, 디스크·크기·진행 막대, 프로그램 행 포커스가 사라진다. `@media (forced-colors: active)`에서 테두리·윤곽선과 시스템 색을 준다(I13의 포커스 규칙을 outline 기반으로 하면 함께 해결).

- [ ] **I51. 앱: 창 크기와 대화상자 높이.** 기본 창(1200×780 논리 px)이 1366×768 @125%(약 1093×614)나 1920×1080 @150%(작업 영역 높이 약 670)에서 화면을 넘어 직접 그린 창 버튼이 화면 밖으로 나갈 수 있다(`tauri.conf.json`, 모니터에 맞추는 코드 없음). 시작할 때 작업 영역에 맞춘다. 공통 `DialogContent`에 최대 높이·스크롤이 없어 900×600에서 저장공간 결과 창이 넘치면 제목·X가 잘린다. 600~720 높이에서 프로그램 화면 고정 머리가 화면의 38%를 차지한다(필터 줄 접기 등). 대화상자나 시트가 열려 있어도 Ctrl+F가 뒤의 검색창으로 간다. "목록 내보내기"를 두 번 누르면 저장 창 호출이 두 번 간다.

- [ ] **I52. 앱: 제거한 프로그램 목록이 앱을 끄면 사라짐.** "방금 제거한 프로그램"이 메모리(`cache.removed`)에만 있어서, 제거 뒤 "다시 시작 필요"를 보고 PC를 다시 시작하면 남은 흔적을 찾을 길이 없다. 제거한 프로그램 정보를 데이터 폴더에 저장해 일정 기간(예: 보관 기간과 같게) 보여 준다. 빈 화면과 제거 결과 창에도 이 목록이 어디 있는지 알리고, 찾지 않은 것이 있으면 사이드바에 표시한다.

- [ ] **I53. 앱: 되돌릴 수 있는 범위를 바로 알려 주기.** 사이드바 아래 "안전하게 정리해요 / 되돌릴 수 있어요" 카드가 모든 화면에 있는데, 프로그램 제거와 저장공간 정리는 되돌릴 수 없고 그 말은 복구 기록 화면에만 있다. 카드 문구를 남은 흔적 정리 범위로 좁히고, 제거 확인 창에 "프로그램 자체는 RobinX로 되살릴 수 없어요"를, 복구 기록 머리에 "다시 설치한 뒤 되돌리면 설정이 돌아와요"를 넣는다. 같은 안내가 여섯 곳에 반복되고 확인 화면 설명이 세 문단이라 경고가 묻히니 줄인다. 강제 제거가 끝나도 "N개를 정리했어요"뿐이라 프로그램이 목록에서 사라졌는지 모른다(강제 제거면 "Old Tool을 제거했어요", 확인 단계에도 한 줄).
- [ ] **I54. 앱: 처음 쓰는 사람을 위한 안내.** "언인스톨러 없음" 카드가 무엇을 하면 되는지 말하지 않고(강제 제거로 이어 주기) "언인스톨러"를 어디서도 풀이하지 않는다. 일반 제거에는 드라이버·보안 모듈·런타임 경고가 없다(`crates/execution/src/force.rs`의 `sensitive_reason`과 같은 판별로, 해당될 때만 "다른 프로그램이 함께 쓸 수 있어요" 한 줄, 막지는 않음). 남은 흔적 줄이 경로만 보여 주니 종류 한 줄("설정 폴더", "시작할 때 자동 실행 등록", "레지스트리 키")을 붙이고, 요약 칩 "연결 정보 일치"와 그룹 제목 "설치 정보와 연결된 흔적"의 낱말을 맞춘다.
- [ ] **I55. 앱: 다음 행동이 없는 곳.** 잔여물 페이지의 흐름 알약 세 개가 버튼처럼 생겼는데 눌리지 않고, 프로그램 화면으로 가는 버튼이 없다(단계 표시 모양 + "프로그램 화면에서 제거 시작"). 복구 기록·저장공간 빈 화면도 다음 행동이 없다. 정리 완료의 "복구 기록 보기"가 방금 만든 백업 카드로 바로 가서 펼치게 한다(삭제는 계속 사용자가 직접). 숨은 예약 작업을 읽어도 끌 방법 안내가 없다("작업 스케줄러 열기"). Store 앱 "설정에서 제거"가 그 앱이 아니라 목록 맨 위를 연다(이름을 복사하고 검색하라고 알리거나 한계를 적음). 시작프로그램 목록에서 가장 눈에 띄는 "등록 위치" 칸은 판단에 도움이 적다(자세히로 옮기는 것 검토).
- [ ] **I56. 앱: 정보와 RobinX 자신.** 설정에 버전·GitHub 이슈 주소·백업 폴더 열기 같은 "정보" 구역이 없다(백업 폴더 열기는 읽지 못한 백업이 있을 때만 나옴). 프로그램 목록에 RobinX 자신이 일반 항목으로 나와, 거기서 제거하면 창이 닫히며 끝난다. 그 행에 "이 앱 자신이에요"를 표시하거나 제거 확인 창에서 알린다. 사이드바 머리 "미리보기"가 "흔적 미리 보기" 기능 이름과 겹치고, 그룹 "관리"·"도구"가 역할을 말하지 않아 복구 기록이 설정 옆에 묻힌다.
- [ ] 🔒 **I57. 위험 표시 색과 페이지 폭 (사용자가 정할 것).** 되돌릴 수 있는 정리(백업하고 정리, 선택 항목 정리)는 빨간 버튼이고, 되돌릴 수 없는 휴지통·캐시 삭제의 "정리하기"는 기본 청록이다. 빨강을 되돌릴 수 없는 동작에만 쓸지 정한다. 페이지마다 내용 폭이 6xl·5xl·4xl·3xl이라 페이지를 옮길 때 제목이 최대 128px 좌우로 움직인다. 두세 단계로 맞출지 정한다.

**3차 점검: 오류 경로·일관성·업데이트**

- [ ] **I62. 앱: 읽기에 실패하면 "없음"이나 끝없는 로딩으로 보임.** 설정을 못 읽으면 보관 기간이 "계속 보관" 하나만, 제외 목록은 "뺀 항목이 없어요", 보관 중 크기는 영원히 자리표시. 정리 확인·결과·복구 기록 안내는 "직접 지울 때까지 보관돼요"라고 잘못 말한다. 오래된 백업 미리 보기가 실패하면 "90일 지난 백업이 없어요". 디스크 사용량 실패는 빈 회색 상자, 설치 목록 실패면 "용량이 큰 프로그램" 카드가 소리 없이 사라진다. 읽지 못한 백업 목록 실패면 그 안내가 안 뜬다. 모두 `isError`일 때 오류와 다시 시도를 보이고, 고르기·삭제 버튼은 막는다. 반대로 이미 불러온 목록이 있는데 새로고침만 실패해도 목록이 통째로 오류 화면으로 바뀌고 위쪽 개수·칩은 옛 숫자로 남는다(프로그램, 시작프로그램, Store, 복구 기록, 저장공간). 데이터가 있으면 목록 위에 "갱신하지 못했어요 · 다시 시도" 띠만 둔다.
- [ ] **I63. 앱: 오류를 보여 주는 방식 통일.** 지금 여섯 가지(ErrorState, 가운데 일반 글자, 아래 줄의 작은 빨간 글자, 4초 알림, 경고 상자, 설치 화면 Problem)다. 오래 남아야 할 오류는 하나의 모양(타일·제목·힌트·복사), 잠깐 알릴 것은 제목 있는 알림으로 나눈다. 알림 약 25곳이 `toast.error(String(e))`라 "액세스가 거부되었습니다. (os error 5)"처럼 무엇이 어디서 실패했는지 없이 4초 뒤 사라진다(제목에 작업과 대상을, 되돌릴 수 없는 작업 실패는 오래 남김). 클립보드 쓰기·Windows 저장공간 설정 열기 실패는 처리하지 않아 아무 반응이 없다. 큰 폴더·큰 파일 찾기 실패는 알림 뒤 카드가 처음 안내로 돌아가 흔적이 없다. 설치 화면 "RobinX 바로 열기" 실패를 삼킨다. 오류·경고 문단 다수가 선택·복사되지 않는다(`data-selectable`). 복사 알림이 세 가지라 공용 복사 버튼(체크로 바뀜, 실패 알림)으로 모으고 경로·명령에 붙인다.
  항목이 크면 나눠서 한다.
- [ ] **I64. 앱: 조용히 일어나는 일 알리기.** 백업 삭제가 권한 오류를 만나면 안내 없이 UAC를 띄운다(다른 곳처럼 "관리자 권한이 필요해요" 단계를 보이고 버튼으로). 앱을 켤 때 만료 백업을 지운 결과(지운 수·못 지운 수)를 어디에도 남기지 않는다(한 번 보여 줌). 정리 중 작업 기록 저장에 실패하면 이미 옮긴 항목이 목록에 남고 다시 누르면 새 작업이 생긴다(다시 찾기나 복구 기록으로 가는 버튼).
- [ ] **I65. 업데이트와 설치 화면.** 업데이트를 받는 중에는 X·Esc·나중에가 모두 막혀 네트워크가 멈추면 창이 영원히 잠긴다(받는 단계에서는 취소나 시간 제한). "마지막 확인" 시각이 실패한 확인에도 갱신된다(성공했을 때만). 릴리스 노트의 마크다운이 기호째 보이고 긴 노트 상자에 스크롤 단서가 없다(가볍게 렌더하거나 평문으로 쓰기로 정함). 설치 화면 완료 제목이 업데이트·다시 설치에도 "설치했어요"다. 설치 완료 경고가 6~7개면 640×480 창에서 "완료" 버튼이 잘린다(경고 목록만 스크롤). 시작할 때 한 업데이트 확인 결과가 늦게 오면 사용자가 열어 둔 정리 창 위에 업데이트 창이 겹쳐 뜬다("지금 업데이트"는 앱을 닫음). 시작 화면이 걷힌 뒤 몇 초 안에 온 결과만 창으로, 그 뒤는 사이드바 알림만.
- [ ] **I66. 앱: 화면마다 다른 모양을 공용 컴포넌트로.** 잘린 이름에 `title`이 없는 곳(잔여물 정리, 시작프로그램 이름, 복구 기록 앱 이름, 큰 프로그램, 큰 폴더, 일괄 제거, 카드 보기 게시자, 제거 창 머리) → 잘리면 툴팁을 붙이는 공용 글자. 카드 머리 네 가지 모양과 위 여백 14·16·22px, 잔여물 정리의 제목과 개수 기준선 5px 어긋남 → 공용 머리. 빈 화면 세로 여백 24~64px와 아이콘 네 가지 → 공용 빈 화면. 결과 화면 세 모양(완료 화면에 남는 "다시 찾기"는 숨김). 칩·배지 세 모양과 소수점 높이 → 둘로. 눌러서 펼치는 행(시작프로그램, 저장공간, 복구 기록 카드 머리)에 hover와 손가락 커서가 없다(프로그램 행·카드 보기도 커서가 다름). 대화상자 구조 두 갈래(머리띠형과 일반형). 시작프로그램 정리 창은 진행 막대 대신 스피너뿐.
  항목이 크므로 나눠서 한다(한 바퀴에 공용 컴포넌트 하나와 그것을 쓰는 곳들).
- [ ] **I67. 앱: 검색창·툴팁·작은 클릭 영역.** 검색창 동작이 화면마다 다르다: 시작프로그램은 Ctrl+F 힌트·동작이 없고, Store 탭은 지우기(X) 뒤 포커스가 사라지고, Enter 동작은 프로그램 화면만 있다(공용 검색창). 프로그램 행 "⋯"에 툴팁이 없다. 테마 버튼은 아이콘이 지금 상태(달)인데 툴팁은 눌렀을 때 결과("라이트 모드로")라 반대 개념이다. 저장공간 체크박스 16px·스위치 36×20을 정확히 눌러야 한다(줄을 눌러도 바뀌게). 한글을 입력하는 중간 자모("ㅋ", "칼")로 검색해 목록이 "조건에 맞는 프로그램이 없어요"와 오가며 깜빡인다(조합이 끝난 값만 쓰거나 짧게 미룸, 세 검색창 모두).
