# 루프 작업 안내

Claude가 `/loop`으로 혼자 이어서 일할 때 읽는 문서. 한 바퀴에 할 일 하나를 끝내고 기록한다.
규칙의 근거는 [CLAUDE.md](../CLAUDE.md)(안전 원칙), 지금까지의 상태는 [HANDOFF.md](HANDOFF.md)에 있다.

## 한 바퀴의 순서

1. **상태 확인.** `git status`가 깨끗한지 본다. 내가 남기지 않은 변경이 있으면 손대지 않고 멈춘 뒤 사용자에게 알린다.
   Git Bash에서는 먼저 `export PATH="$(cygpath -u "$APPDATA")/npm:$HOME/.cargo/bin:$PATH"`.
2. **할 일 고르기.** 아래 목록에서 위쪽부터 `[ ]`인 첫 항목. 🔒 표시가 있으면 건너뛴다.
   항목이 한 바퀴에 끝나지 않을 만큼 크면, 먼저 목록에서 작은 항목들로 나누고 첫 조각만 한다.
3. **만들기.** 항목의 "끝난 기준"을 그대로 따른다. 관련 없는 파일은 고치지 않는다.
4. **확인.**
   - 앱 코드: `pnpm check` 통과. 화면이 바뀌면 `pnpm tauri dev`로 띄워 DevTools 포트(9223)로 실제 화면을 본다.
   - 삭제·정리·최적화 동작은 테스트 앱(`robin-fixture`)과 디버그 전용 테스트 항목으로만 시험하고, 끝나면 `robin-fixture remove`.
   - 웹사이트: `website/README.md`의 빌드와 taste-skill 검사(FAIL 0), 그다음 `bash website/scripts/deploy.sh`.
   - 문서만 바꿨으면 링크와 명령이 실제로 있는지만 확인한다.
5. **기록.** 커밋 메시지는 영어, 끝에 `Co-Authored-By` 줄. `main`에 커밋하고 push한다.
   이 문서의 항목을 `[x]`로 바꾸고 날짜와 커밋 해시를 붙인다. 아래 "바퀴 기록"에 한 줄 남긴다.
6. **다음 바퀴.** 할 수 있는 항목(🔒 아님)이 남았으면 다음 바퀴를 예약한다. 없으면 루프를 끝내고 사용자에게 🔒 항목 목록과 필요한 행동을 보고한다.

### 멈추고 🔒로 표시할 때

다음이 필요해지면 그 앞까지 한 것만 확인해 커밋하고, 항목에 🔒와 이유(사용자가 할 일)를 적은 뒤 다음 항목으로 간다.

- UAC "예", 로그인, 저장 창 확인처럼 사용자의 손이 필요한 것
- GitHub Release 공개(`scripts/release.sh --publish`) 같은 공개 행동
- 정한 원칙(삭제 원칙, 최적화 원칙)이나 기본값을 바꾸는 결정
- 외부 서비스에 무엇을 보내거나 계정 설정을 바꾸는 것

### 절대 하지 않는 것

- 실제 프로그램 제거, 실제 잔여물·캐시 삭제, 실제 시작 항목·설정 변경 (읽기만 한다)
- 비밀 키(`%USERPROFILE%\.tauri\robinx-updater.key`) 출력·커밋·전송, `docs/private/`·`Revo Uninstaller Pro.zip` 커밋
- 분석한 외부 프로그램(GPL 등)의 코드 복사
- `pnpm check`가 실패한 채로 커밋. 한 바퀴 안에 못 고치면 내 변경을 되돌리고 항목에 오류를 적어 🔒
- `--no-verify`, 강제 push, 다른 사람이 남긴 변경 덮어쓰기

## 할 일 (위가 먼저)

### A. 정리해도 공간이 안 늘어나는 문제 (2026-10-19 사용자 지적)

남은 흔적은 같은 드라이브에 백업되므로 백업을 지워야 공간이 돌아온다. 보관 기간 기본값은 "계속 보관"이다.

- [ ] **A1. 공간 상태를 솔직하게 보여 주기.** 정리 결과 화면과 복구 기록에 "백업으로 보관 중 N — 백업을 지우거나 보관 기간이 지나야 공간이 돌아와요" 표시. 저장공간 정리(캐시)는 바로 공간이 생긴다는 점과 구별한다.
  끝난 기준: 테스트 앱 정리 후 두 화면에서 문구와 크기가 맞게 보임, `pnpm check` 통과.
- [ ] **A2. 오래된 백업 한 번에 비우기.** 복구 기록에 "N일 지난 백업 비우기"(지울 크기 표시, 되돌릴 수 없다는 경고, 한 번 더 확인). 작업별 "백업 삭제"는 이미 있다. 관리자 권한 백업은 기존 `--elevated-delete` 경로를 쓴다.
  끝난 기준: 테스트 백업으로만 시험, 실제 백업은 건드리지 않음.
- [ ] 🔒 **A3. 보관 기간 기본값을 "계속"에서 30일로.** 사용자 결정 필요 (추천: 30일, 이미 고를 수 있는 값). 기존 사용자의 저장된 설정은 바꾸지 않는다.
- [ ] **A4. 격리 폴더 NTFS 압축 검토.** 테스트 앱 흔적과 합성 데이터(텍스트·이미 압축된 파일)로 압축 전후 크기와 정리 시간을 잰다. 줄어드는 비율이 작거나 복원이 복잡해지면 하지 않고 결과만 PLAN.md에 적는다.

### B. 앱 문구 다듬기

사이트처럼 Humanizer 체크리스트(과장, "X가 아니라 Y", 마무리 한 줄, 억지 세 가지 나열, 장식 굵은 글씨)와 한국어 상투어를 찾아 고친다. 문장이 코드 동작과 맞는지도 대조한다. 화면 하나씩:

- [ ] B1. 프로그램 (`src/features/programs`)
- [ ] B2. 남은 흔적 (`src/features/leftovers`)
- [ ] B3. 복구 기록 (`src/features/restore`)
- [ ] B4. 저장공간 (`src/features/storage`)
- [ ] B5. 시작프로그램 (`src/features/startup`)

끝난 기준: 화면을 띄워 바뀐 문구가 잘리지 않는지 확인, `pnpm check` 통과.

### C. 실제 프로그램으로 정확도 시험 (Windows Sandbox)

실제 PC에서는 지우지 않는다는 원칙을 지키면서 실제 프로그램을 시험하는 방법. Sandbox는 창을 닫으면 모두 사라진다.

- [ ] **C1. Sandbox 준비물 만들기.** `scripts/sandbox/`에 `.wsb` 설정(빌드한 `robinx.exe`와 설치 파일 폴더를 읽기 전용으로 연결), 시험할 무료 프로그램 목록(7-Zip, VLC, Notepad++ 등 10~20개), 기록 양식(프로그램마다 미리 고른 항목·검토 항목·잘못 고른 항목).
  끝난 기준: 문서와 설정 파일만, 실행은 C2.
- [ ] 🔒 **C2. Sandbox 켜고 시험.** "Windows 샌드박스" 기능 켜기에 UAC와 재부팅이 필요하다. 사용자 승인 뒤 진행. 결과는 `docs/sandbox-results.md`에.
